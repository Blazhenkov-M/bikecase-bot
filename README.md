# Проект: Telegram-bot для веломастерской

## Стек
- Python 3.12
- aiogram 3.x (версию зафиксировать в requirements.txt)
- SQLAlchemy 2.0 (async), PostgreSQL, Alembic
- openpyxl для xlsx-отчётов

## Структура
- `handlers/` — роутеры (по одному модулю на раздел)
- `keyboards/` — клавиатуры
- `services/` — бизнес-логика
- `database/` — модели, сессии, репозитории

## Описание проекта
Бот для веломастерской, которая организует трансфер велосипедов клиентов на гонки и спортивные мероприятия (триатлон).

Админ создаёт событие, клиент регистрируется на него, после чего админ получает все заявки в xlsx-таблице.

### Правила работы
- **Одновременно существует только одно активное событие.** Новое событие нельзя создать, пока не завершено текущее. Поэтому клиент не выбирает событие: заявка всегда подаётся на активное.
- **Один клиент = один велосипед = одна заявка** на событие.
- **Точки приёма и выдачи фиксированы** (одни и те же для сдачи и получения), время везде 11:00–20:00:
  - «Староватутинский» и «Заповедная» — мастерские, работают каждый день, у них одинаковые даты приёма (обычно 4–6 дней)
  - «Крылатское» — свой диапазон дат приёма (обычно 2–3 дня)
- **Даты приёма и выдачи — диапазоны** (с даты по дату), по той же схеме групп точек. Даты показываются клиенту при выборе точки.
  - В мастерских клиент день не выбирает, приезжает в любой день в пределах диапазона.
  - В «Крылатском» велосипеды грузят в машину, мест ограниченно: клиент выбирает **конкретный день** и при сдаче, и при получении. Админ задаёт два лимита — мест в день на приём и мест в день на выдачу (одно число на все дни диапазона). Заполненные и прошедшие дни клиенту не предлагаются; если свободных дней нет, «Крылатское» скрывается из выбора.
  - Сузить даты «Крылатского» так, чтобы уже записанные клиенты оказались вне диапазона, нельзя. Уменьшение лимита принятые заявки не трогает.
- **Оплаты в боте нет.** Цена события только показывается клиенту.
- **Данные не удаляются.**
  - Отмена заявки = смена статуса на «отменена».
  - Завершённое событие помечается как прошедшее (архив), его заявки остаются в базе.
- Согласие на обработку ПДн: сохраняется факт согласия и дата в БД.
- Уведомлений (напоминаний, оповещений админа) пока нет.

## Функционал

### Меню админа (кнопки)
1. **«События»**
   - «Создать событие» — шаги: название мероприятия → цена → даты приёма «Заповедная»/«Староватутинский» (диапазон) → даты приёма «Крылатское» (диапазон) → даты выдачи «Заповедная»/«Староватутинский» (диапазон) → даты выдачи «Крылатское» (диапазон) → мест в день на приём «Крылатское» → мест в день на выдачу «Крылатское»
   - «Редактировать событие»
   - «Закрыть регистрацию» (на событие)
   - «Завершить событие» (пометить как прошедшее)
2. **«Заявки»** — счётчики текущего события: всего активных и отменённых, по точкам сдачи и выдачи, «Крылатское» по дням в виде «занято/лимит». Кнопка «Обновить».
3. **«Скачать xlsx-отчёт»** — одно событие = один файл. Колонки: №, имя, фамилия, телефон, велосипед, точка сдачи, дата сдачи, точка выдачи, дата выдачи (для «Крылатского» — выбранный день, для мастерских — диапазон). Отменённые заявки в отчёт не попадают.

### Меню клиента
- **«Оформить заявку»** — шаги: согласие на ОПД → имя → фамилия → телефон → марка велосипеда → цвет велосипеда → точка сдачи в Москве (для «Крылатского» — ещё и день) → точка получения в Москве после мероприятия (для «Крылатского» — ещё и день)
- **«Мои заявки»** — просмотр, редактирование, отмена
- **«Поддержка»** — ссылка на Telegram админа

## Модель данных (черновик)
- `events`: id, название, цена, даты приёма (заповедная/староватутинский: с–по), даты приёма (крылатское: с–по), даты выдачи (те же две группы: с–по), лимиты «Крылатского» (мест в день на приём / на выдачу), статус (`active` / `registration_closed` / `finished`)
- `applications`: id, event_id, user_id (telegram), имя, фамилия, телефон, марка и цвет велосипеда, точка сдачи, точка выдачи, день сдачи и день выдачи (только для «Крылатского»), статус (`active` / `cancelled`), дата создания
- `users` (или поля в заявке): telegram_id, факт согласия на ОПД, дата согласия
- Ограничение: уникальность (event_id, user_id) для активных заявок
## Запуск

`.env` в корне проекта (в git не попадает):
```
BOT_TOKEN=...
DB_HOST=postgres
DB_PORT=5432
DB_USER=...
DB_PASS=...
DB_NAME=...
ADMIN_IDS=111,222          # или [111,222]
# DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/dbname  — если задан, DB_* для бота не нужны
# SUPPORT_URL=https://t.me/...  — ссылка кнопки «Поддержка»
```

Docker (миграции применяются автоматически при старте контейнера):
```
docker compose up -d --build
```

Локально (нужен доступный Postgres и `DATABASE_URL` с `localhost`):
```
pip install -r requirements.txt
alembic upgrade head
python main.py
```

Админ открывает меню по `/start` или `/admin`.
